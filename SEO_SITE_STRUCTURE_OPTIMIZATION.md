## Header Hierarchy Analysis

### Header Standards

**Rules to follow across all pages:**
- Maximum 1 H1 per page (primary keyword focus)
- 2-3 H2 tags per page (secondary keywords)
- 3-6 H3 tags per page (supporting topics, LSI keywords)
- Maintain logical, sequential hierarchy (no skipping levels)
- Natural keyword integration without stuffing

### Cross-Silo Linking Strategy

Only link across silos when:
1. Contextually relevant (e.g., water damage → mould prevention)
2. User journey flows naturally (e.g., service → insurance claims)
3. Secondary concern is mentioned (e.g., fire damage → water damage from firefighting)

**Allowed Cross-Silo Links:**
- Water Damage → Mould Remediation (moisture control)
- Fire Damage → Water Damage (firefighting water)
- Any Service → Insurance Claims (claims support)
- Any Service → Service Areas (geographic relevance)
- Any Service → Emergency Services (urgent response)

### Internal Linking Best Practices

1. **Hub-Spoke Pattern:** Each hub page links to all spoke pages
2. **Reciprocal Linking:** Spoke pages link back to hub
3. **Contextual Links:** Related spokes link to each other (max 3-4 links)
4. **Anchor Text:** Use descriptive, keyword-rich anchor text
5. **Link Depth:** Maintain max 3 levels of directory depth
6. **Follow/NoFollow:** All internal links should use rel="follow"

### Linking Recommendations by Page Type

**Hub Pages (Main Service Pages):**
- Link to all 3-6 spoke pages
- Link to relevant guides
- Link to relevant FAQ section
- Link to insurance claims support

**Spoke Pages (Specific Services):**
- Link back to parent hub
- Link to 2-3 related spokes
- Link to 1-2 relevant guides
- Link to related FAQ entries

**Guide Pages:**
- Link to relevant service pages
- Link to related guides in same category
- Link to FAQ for more information

**FAQ Pages:**
- Link to relevant service pages
- Link to related guides for deeper information

## URL Structure

### URL Structure Guidelines

**General Rules:**
- Maximum 75 characters
- Use hyphens as separators
- Lowercase only
- Meaningful, descriptive segments
- No parameters or tracking codes
- No dynamic query strings

### URL Patterns by Page Type

```
/                                                    # Homepage
/services                                            # Services hub
/services/[category]                                 # Service category
/services/[category]/[specific-service]             # Specific service
/service-areas                                       # Service areas hub
/service-areas/[location]                           # Location-specific
/about-phil-mcgurk                                   # About page
/guides                                              # Guides hub
/guides/[category]                                   # Guide category
/guides/[category]/[specific-guide]                 # Individual guide
/faq                                                 # FAQ hub
/faq/[category]                                      # FAQ category
/insurance-claims                                    # Insurance claims
/insurance                                           # Insurance partners
/insurance/[company-name]                           # Insurance company
/emergency                                           # Emergency hub
/emergency/[scenario]                               # Emergency scenario

```

### Canonicalization Strategy

- Set canonical URL in page head
- Redirect duplicate URLs to canonical version
- Use canonical for www vs non-www (prefer non-www)
- Remove tracking parameters from canonical

## Quick Reference Guide

### For Content Creators

**When creating a new service page:**

1. Use correct H1 matching the service type
2. Add 2-3 H2 tags for major sections
3. Use 3-6 H3 tags for subsections
4. Link to hub page in first paragraph
5. Link to 3-4 related service pages
6. Link to 1-2 relevant guides
7. Link to FAQ section
8. Add breadcrumb navigation
9. Set canonical URL
10. Include schema markup

**When creating guides:**

1. Follow `/guides/[category]/[specific-topic]` URL pattern
2. Link back to relevant service page
3. Link to related guides in same category
4. Link to FAQ for more info
5. Use proper heading hierarchy
6. Include 3-5 internal links minimum

### For Developers

**When implementing a new page:**

1. Check `PAGE_HIERARCHIES` in `site-structure.ts` for header requirements
2. Use `getPageLinks()` from `internal-linking.ts` for link recommendations
3. Implement breadcrumb using `BreadcrumbNavigation` component
4. Use `getBreadcrumbSchemaForPath()` for schema markup
5. Validate URL using `validateURLStructure()`
6. Set canonical using `getCanonicalURL()`
7. Include page in `SITEMAP_INDEXES` with correct priority
8. Test with Chrome DevTools accessibility audit

**When updating existing pages:**

1. Ensure H1 is unique and descriptive
2. Check internal links are still relevant
3. Update sitemap lastmod date
4. Verify breadcrumbs are correct
5. Ensure canonical URL is set
6. Test mobile navigation
7. Verify footer links are working

### For Site Audits

**Check these regularly:**

- [ ] All pages have exactly 1 H1
- [ ] Header hierarchy follows structure (no skipped levels)
- [ ] Breadcrumbs display correctly
- [ ] Internal links use descriptive anchor text
- [ ] Footer links are organized by section
- [ ] Sitemap.xml is up to date with correct priorities

## Common Issues & Solutions

### Issue: Pages not ranking for target keywords

**Solutions:**
1. Verify H1 matches primary keyword
2. Check for proper internal linking from hub
3. Ensure page is in high-priority section of sitemap
4. Review competitor H1 tags
5. Verify keyword appears in first 100 words

### Issue: Low click-through rate from SERP

**Solutions:**
1. Review meta title and description
2. Check if page title matches H1
3. Improve meta description to include action words
4. Add rich snippets/schema markup
5. Review breadcrumb display in SERP

### Issue: Broken internal linking structure

**Solutions:**
1. Audit current internal links
2. Use linking clusters to reorganize
3. Update hub pages first
4. Then update spoke pages
5. Test all links in staging before deployment
