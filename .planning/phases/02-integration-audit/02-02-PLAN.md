# Plan 02-02: Document Disconnected Endpoints and Required Connections

## Objective

Using the audit table from 02-01-RESULTS.md as input, produce two deliverables:

1. **GAP-REPORT.md** — structured list of every DISCONNECTED route with
   diagnosis (was it intentionally skipped, missing UI, missing hook, or
   orphaned route?)
2. **CONNECTIONS-REQUIRED.md** — actionable work items for Phase 5, one item
   per gap, with the specific file(s) that need to be created or modified

---

## Prerequisites

- `02-01-RESULTS.md` must exist and be complete (all 345 routes audited)
- Phase 1 (TypeScript fix) must be done — tsc exits 0

## Step-by-Step Execution

### Step 1 — Extract all DISCONNECTED and PARTIAL rows

From `02-01-RESULTS.md`, filter rows where Status is `DISCONNECTED` or
`PARTIAL`. List their route paths.

Grep pattern for the results file:
```
grep "DISCONNECTED\|PARTIAL" .planning/phases/02-integration-audit/02-01-RESULTS.md
```

---

### Step 2 — Diagnose each gap

For each disconnected route, determine the root cause by reading the route file
and checking related dashboard pages. Categories:

**A — Missing UI page:** A route exists and is functional, but no dashboard
page or component renders a UI that calls it. The fix is to add a fetch call to
an existing page or create a new page.

**B — Missing hook:** A route is called in one place via raw fetch but should
be centralised in a reusable hook in `apps/web/hooks/` or
`apps/web/hooks/client/`. The page exists but the wiring is missing.

**C — Orphaned route:** The route was built for a feature that never had a
frontend built. No page, no component, no hook references it. Needs a UI to be
created, or the route needs to be flagged for removal.

**D — Partial method gap:** A route exports both GET and POST, but the frontend
only calls GET. The POST path is disconnected.

**E — Webhook-only (false positive):** Route was originally marked DISCONNECTED
but is correctly only called by external services (Stripe, Xero, cron jobs).
Reclassify as WEBHOOK-ONLY and exclude from the work list.

**Diagnosis method:**
1. Read the route file: `apps/web/app/api/<path>/route.ts`
   - Look at which Prisma models it reads/writes
   - Identify what feature domain it belongs to
2. Check the corresponding dashboard feature page, if one should logically exist
3. Search components for commented-out or placeholder fetch calls:
   ```
   grep -rn "TODO\|FIXME\|placeholder\|coming soon" apps/web/app/dashboard/ apps/web/components/
   ```
4. Check git history for the route file to see if it was ever connected:
   ```
   git log --oneline --follow apps/web/app/api/<path>/route.ts
   ```

---

### Step 3 — Assess severity

For each gap, assign a severity:

| Severity | Criteria |
|----------|----------|
| P0 — Critical | Gap blocks a core user flow (payment, claim submission, contractor matching) |
| P1 — High | Gap means a dashboard section shows no data or errors |
| P2 — Medium | Gap means an analytics or secondary feature is empty |
| P3 — Low | Gap means an admin-only tool is unavailable |

**Core flows to protect (from ROADMAP Phase 5):**
1. Client payment → Stripe → Database → Email notification
2. Contractor job completion → Payment calculation → Payout
3. Real-time updates → Supabase → Frontend refresh
4. AI image enhancement → Processing → Result delivery
5. Webhook handling → Idempotency → State update

Any gap touching these flows is P0.

---

### Step 4 — Draft the connection spec for each gap

For each P0 and P1 gap, write a connection spec with:

- **Route:** the disconnected API path
- **Expected caller:** which page or component should call it
- **HTTP method(s) needed:** which exported methods to wire up
- **Trigger:** what user action fires the request (button click, page load, form submit)
- **Required changes:**
  - File to modify (existing page or component)
  - Or file to create (new page, new hook)
  - Specific lines to add (fetch call, form action, useEffect dependency)

For P2/P3 gaps, write a shorter entry: route path + one-line description of
what UI should call it.

---

### Step 5 — Check for reverse gaps (frontend calls missing routes)

Search for fetch calls in the dashboard that point to routes that do NOT have
a `route.ts` file:

```
grep -rn "fetch.*'/api/" apps/web/app/dashboard/ apps/web/components/ apps/web/hooks/ \
  | grep -oP "'/api/[^'?]+" | sort -u
```

Cross-reference this list against the 345 known routes. Any path in the fetch
list that is NOT in the routes list is a missing route — the frontend calls an
API that does not exist. These are equally critical and must be documented.

Label these: **MISSING-ROUTE** in the connections report.
