# Plan 02-01: Audit All API Routes for Frontend Consumers

## Objective

Produce a complete, row-per-route audit table that records every `route.ts`
file under `apps/web/app/api/`, identifies the HTTP methods it exports, and
lists every frontend file (page, component, or hook) that calls it. Mark each
route as CONNECTED, PARTIAL, or DISCONNECTED. This table becomes the source of
truth for Phase 5 (API Completion).

---

## Scope

Total route files to audit: **345** `route.ts` files (verified count).
The ROADMAP groups them into four billing domains:

| Domain              | Path prefix                      | route.ts count |
|---------------------|----------------------------------|----------------|
| Admin               | /api/admin/                      | 62             |
| Client              | /api/client/                     | 34             |
| Contractor (scoped) | /api/contractor/                 | 26             |
| Payments / Stripe   | /api/payments/, /api/stripe/     | 8              |
| Shared / Public     | All remaining prefixes           | ~215           |

---

## Step-by-Step Execution

### Step 1 — Enumerate all route files

Run the following command and capture the output to a working scratch list:

```
find apps/web/app/api -name "route.ts" | sort
```

This produces the 345 file paths. Group them by first path segment after
`/api/` (admin, client, contractor, payments, stripe, auth, analytics, etc.).

---

### Step 2 — For each route file, extract HTTP method exports

Read each `route.ts` and note which of these named exports exist:
`GET`, `POST`, `PUT`, `PATCH`, `DELETE`

Pattern to grep per file:
```
grep -n "^export async function \|^export const " <route.ts>
```

Record the methods in the audit table column `Methods`.

---

### Step 3 — Search for frontend consumers

For each API path string (e.g. `/api/admin/kpis`), search all frontend source
files for callers. Frontend files to search:

**Primary locations:**
- `apps/web/app/dashboard/**/*.tsx`
- `apps/web/app/(dashboard)/**/*.tsx`
- `apps/web/components/**/*.tsx`
- `apps/web/hooks/**/*.ts`
- `apps/web/hooks/client/**/*.ts`
- `apps/web/app/**/page.tsx` (public pages that may call APIs)

**Grep patterns to use:**

```
# Direct fetch calls
grep -rn "fetch.*'/api/<path>" apps/web/app/dashboard/ apps/web/components/ apps/web/hooks/

# Template literal fetch
grep -rn 'fetch.*`/api/<path>' apps/web/app/dashboard/ apps/web/components/ apps/web/hooks/

# Dynamic URL construction (catches pagination params, etc.)
grep -rn "new URL.*'/api/<path>\|'/api/<path>" apps/web/app/ apps/web/components/ apps/web/hooks/
```

For dynamic segments (e.g. `/api/admin/contractors/verification/[contractorId]/route.ts`),
search for the static prefix:
```
grep -rn "'/api/admin/contractors/verification/" apps/web/app/ apps/web/components/ apps/web/hooks/
```

Record matched file paths in the `Consumers` column.

---

### Step 4 — Check hook-wrapped calls

Several APIs are called via custom hooks rather than raw fetch. Check these
hook files explicitly:

- `apps/web/hooks/client/useServiceRequests.ts` → client API paths
- `apps/web/hooks/client/useClientAnalytics.ts` → `/api/client/analytics/`
- `apps/web/hooks/client/useClaimWorkflow.ts` → `/api/client/claims/`
- `apps/web/hooks/useAdminRealtimeJobs.ts` → `/api/admin/jobs/live`
- `apps/web/hooks/useRealtimeSubscription.ts` → `/api/realtime/billing/`

For each hook, record which API path it calls and which page.tsx files import
that hook (grep `import.*useServiceRequests`, etc. across dashboard pages).

---

### Step 6 — Populate the audit table

For each route, write one row in the output file (see Expected Output below).

Status values:
- **CONNECTED** — at least one frontend file calls this route
- **PARTIAL** — route exists and is called, but only some methods are used
- **DISCONNECTED** — no frontend caller found
- **WEBHOOK-ONLY** — route is only called by external services (Stripe, Xero, cron)
- **ADMIN-ONLY** — called only from server-side admin tooling, not browser UI

---

### Step 7 — Perform per-domain sub-audits

Process each domain in order. Suggested order:

1. `/api/admin/` (62 routes) — match against `app/dashboard/admin/**`
2. `/api/client/` (34 routes) — match against `app/dashboard/client/**`
3. `/api/contractor/` (26 routes) — match against `app/dashboard/contractor/**`
4. `/api/payments/` + `/api/stripe/` (8 routes) — match against client/contractor payment pages
5. All remaining routes — match against public pages and shared components
