## 📋 Documentation Standards

### When to Create Documentation

- **New features**: Document in relevant guide
- **Architecture changes**: Update CLAUDE.md
- **Breaking changes**: Update README.md and relevant guides
- **Security updates**: Update SECURITY.md
- **API changes**: Update docs/api/

### Documentation Style

- Use clear, concise language
- Include code examples
- Provide quick reference tables
- Link to related documentation
- Keep examples up-to-date

### Updating Documentation

1. Make changes to relevant files
2. Update this index if needed
3. Commit with descriptive message: `docs: update <topic>`
4. Keep archived docs as historical reference

## 🔄 Maintenance

### Documentation Review Schedule

- **Weekly**: Check for outdated links
- **Monthly**: Review accuracy of guides
- **Quarterly**: Major documentation audit
- **Per Release**: Update version-specific info

### Archive Policy

Documents are moved to `docs/archive/` when:
- Superseded by newer documentation
- Implementation is complete (COMPLETE.md, SUMMARY.md files)
- Historical value only (audits, reports)
- No longer actively referenced

Documents remain in root or guides when:
- Actively used for development
- Core project documentation
- Living documents (updated regularly)
